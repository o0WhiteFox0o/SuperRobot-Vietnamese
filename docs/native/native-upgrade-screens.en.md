# Modification screen: body list, native takeover of five modifications and weapon modifications

Date: 2026-09-22. Status: The five screens of **ユニット transformation (aircraft list, five transformations) and weapon transformation (aircraft list, weapon list, transformation confirmation) have been taken over and verified on the actual machine; the successful step of the actual weapon transformation (post-deduction, value-adding, modification of additional weapon prompts) has not been completed due to insufficient archive funds. The method is the same as [Interfield Main Menu](native-intermission-menu.md): the original initialization function skips drawing, and the native page draws the same panel according to the layout rectangle in the ROM; choose to just write the cursor and inject an A/B edge into the original each frame function. The modification value, price, upper limit, spread, and EW dress-up are still determined by the original function and the hook of [15-segment modification rules](../gameplay/upgrade-limits.md).

## 2. Takeover method

Source code: [`upgrade_page.cpp`](../../src/host/upgrade_page.cpp) (game thread adapter), [`frontend.cpp`](../../src/native/ui/frontend.cpp)'s `upgrade_sync` (page), [`game_hooks.cpp`](../../src/host/game_hooks.cpp)'s wrapper. When the original version is selected in the "Inter-field screen" on the settings page, all four construction entries are returned to the original screen (`original_screens()`, and the page that is still open is closed at the same time); `SRW64_NATIVE_UPGRADE=0` or when the profile is not loaded, the original screen is retained throughout the entire run.

| original function | wrapper |
| --- | --- |
| `801CF388`／`801D03D0` List initialization | Do not adjust the original function. Reserved: background calls (including random numbers), list generation functions, cursor restoration by pressing `D_801DECD4`, recalculation of selected aircraft; layout, text, and cursor sprites will not be built. Fade in after posting snapshot. |
| `801CF564`/`801D04A4` list per frame | When the input is filtered to 0, the original function is written with zero and is called as usual. **Caliber of 15 segment rules**: Each item in the snapshot contains `level`, `cap` (the effective upper limit is `allowed_cap`: the breakthrough is 15), `original_cap`, `price`/`preview` (only available when the number of segments < the effective upper limit, the table in the memory is read directly, and the rule file patch takes effect) and `gauge`. The rules of the scale string are consistent with `upgrade_rules.hpp`: within the upper limit of the original work ▶/▷, and beyond ●/☆; turn on the breakthrough and draw to the effective upper limit, turn off and draw only to the existing number of segments. "Maximum N stages" displays the effective upper limit; when the rules raise the upper limit (`original_cap` < `cap`), the fund/expense box and the weapon confirmation screen of the five screens each have one more line `upgrade_cap_original` (original upper limit of N stages ▶▷ · Upper limit breakthrough ●☆), allowing players to distinguish the inherent number of stages and the number of breakthrough stages. The two scope hooks of the original version have not been changed, so whether it can be changed and how much money will be deducted is still determined by the original version after `+0x51` is rewritten by the scope - the adapter just uses the same `allowed_cap` to determine which window to pop up.

**Snapshot**: `status.upgrade_page`: `screen` (`list`/`stats`/`weapons`/`weapon` ), `kind` (`stats`/`weapons`), `serial`, `funds`, `cursor`; the list is `page`(0 (from), `pages`, `rows[]` (`slot`, `number`, `name`, __INL_COD E_180__, `en`, `mobility`, `armor`, `limit`, `pilot`); five items are `unit` (`slot`, `number`, `name`, `art`), __INL_CODE_191 __, `rows[]` (above), `window` (empty/`confirm`/`maxed`/`poor`); the weapon list is `rows[]` (`index`, `number`, `name`, `power`, `range_min/max`, __ INL_CODE_203__, `critical`, `en`, `morale`, `skill`, `ammo`, __IN L_CODE_209__, `terrain`, `level`, `type`, `cap`, `price`, __INL_ CODE_215__, `gauge`), `unit.en`/`unit.morale`, `window` (empty/`bonus`); the confirmation screen has `weapon` (same line), `cursor` (はい 0／いいえ 1), `window`. Event log `upgrade-page-events.jsonl`.

**Page**: The list panel is laid out in a 0x6B rectangle, and the column positions are as in the original version; the five screens are divided into five sections according to the original screenshots: aircraft name, questions, funds/expenses, aircraft diagram, and five elements (the original layout only has one outer frame, and the internal separation is drawn by the original sprite, here it is determined according to the screenshot). The body diagram uses the battle pose imported from the local ROM (`battle_assets.units`). The confirmation window and message window are laid out in a rectangle of 0x74/0x87.

**Funds**: The fund figures on the three screens can be modified directly by clicking on them (see Section 6a of [Inter-site Main Menu](native-intermission-menu.md)). The modification will immediately affect the cost judgment and deduction.

**Debug**: Stable ID `upgrade:N` (line; click on the current line to confirm, click on other lines to move the cursor), `upgrade-confirm`, `upgrade-cancel`, `upgrade-dismiss`; keyboard ↑↓, ←→ (list page turning), Enter/Z, Esc/X.
