# Protagonist selection and confirmation page

The protagonist selection and name editing at the opening will be taken over from 2026-09-11, and the protagonist selection page will be added on 2026-09-18. **Players will no longer be allowed to change their names starting from 2026-09-27**: After selecting the protagonist, the default names of the two people are written. There are only two steps left on the name page: casting and confirmation. The default names are displayed according to the reading language, see [Default name trilingual display](default-names.md). The page is a shared SDL/RmlUi page, which is drawn directly in the game window, covering the original word selection table and confirmation UI, and does not open a sub-window (AppKit will no longer be used from 2026-09-22).

## Use

Restart `scripts/Play SRW64 Native.command`, select a new game, skip the public prologue and then the protagonist selection page will appear. After confirmation, enter the confirmation page. Both steps share a set of page headers, and the interface copy is available in Japanese, Chinese, and English. The page can be used in both Original and HD modes. For the character avatar, you can choose the original image or the registered HD image according to the mode.

- **Protagonist Selection** (2×2 cards starting from 2026-09-30, the design draft can be found in Claude's canvas "SRW64 Protagonist Selection Redesign" plan C): There are four cards in two rows and two columns, in the original order - ブラッド (super type, male), Malima (super type, female) in the upper row, アークライト (real type, male), セレイン (real type, female) in the bottom row. On the upper left side of each card is a diagonal route label (super orange, real blue). Below, two **same size** portraits of the protagonist and his partner are side by side, each labeled "Protagonist/Partner" and the default name (reading language). The side length of the avatar is calculated from the window: the height of the card minus the margin after tags, annotations and names, approximately 100 dp (150 pixels) in Deck Extra Large format.
- Operation: ←→ loop according to the original order, ↑↓ to change line; Enter/Z/A to confirm; click the mouse or touch to highlight the card, and then press "Continue: Confirm". The bottom bar displays the key prompts (`select_keyboard_hint`, under the handle is the `_pad` version).
- Sound effects: Play the original cursor sound when switching, and play the original confirmation sound when confirming.
- The original page has not been returned, and neither has this page.
- **Confirmation page**: Two horizontal cards in the upper row (the protagonist card is outlined in cyan), each with a route label, a box avatar, a full name and "/nickname" (reading language, the full name is connected with the separator of the language); the two cards in the lower row show the **initial body**: body pose diagram (use the entire HD pose in HD mode, `battle_assets.units` registered `hd`), body name (text) `0x20F + 机体号`, depending on the reading language, the host will rename it when switching languages) and "driver nickname". The initial body of each route is written in `native_name_entry.cpp``route_units`：アースゲイン(34)／ヴァイローズ(35)、スイームルグ(36)／エルブルス(37), ソルデファー(30)/ノウルーズ(327), スヴァンヒルド(32)/シグルーン(328). "Start story" (Enter/Z/A) enters the plot along the original entrance; "Return to character selection" (Esc/X/B) returns to the casting page, keeping the original highlight.
- **Window scaling**: The page is typeset according to the dp size of the window (`NamePage::build` uses the size and dp ratio of `context` to calculate the avatar and card size, and rebuilds it when the window or interface size changes), and the avatar is resampled according to the display width through `NameActions::image`. When SDL updates the Metal layer in advance, it also synchronizes the Plume drawable description size to avoid using the last window size for dialogue after returning to the plot.
- **Switch language**: F7 or set to switch language, the page will be rebuilt immediately in the new language.

The next time a new game enters the protagonist selection, the original page will be used; `SRW64_NATIVE_NAME_ENTRY=0` will retain the original version for the entire run. The original page cannot be renamed either: after the original "はい", the host writes the default name, sets `801C70F4 = 2`, fades out and goes directly to the route prologue, without entering the original word selection page (2026-09-27, this section of the check has been added to the script, and it has not yet been run on the actual machine). `SRW64_NATIVE_NAME_ENTRY=0` still retains all original pages and is only used to reproduce the old baseline.

Code distribution:
- bridged at `src/host/native_name_entry.cpp`;
- Native UI in `src/native/ui/name_page.cpp` (RmlUi);
- The glyph decoding is in `src/native/game_adapter/name_codec.hpp`, and the default name table is in `src/native/game_adapter/default_names.hpp`;
- The interface entries are in `content/locales/{ja,zh-Hans,en}.json` (`select_*`, `name_*`, `review_keyboard_hint`, and the key names are registered in `UI_KEYS` of `src/srw64_native/profile.py`).

The platform UI only receives immutable requests and reports semantic actions; only the game thread reads and modifies RDRAM, and the UI thread does not call the original function.

**Hook**: Intercept four pairs of functions of ROM `0x1090A0`:
- `801C5004/801C50B8`: Protagonist selection;
- `801C5494/801C5644`, `801C5920/801C5AD0`: Edit the names of the protagonist and partner; they will no longer be opened on the native page, and will be returned to the original version only when the writing fails;
- `801C5DAC/801C5E88`: Final confirmation.

Cover the original screen immediately after initialization, and accept the operation only after the original fade-in is completed.

When **selecting a route**, the game thread processes it in the order of the original "はい": confirmation sound, recording the route, resetting the template when the route changes and calling `801C3744`. Then write the default name: put the first name, last name, and nickname (the first name is cut into 5 spaces, the アークライト is cut into 3 spaces, the same as `801C3744`) into the editing buffer `801C71E0`, and the original verification function `801C474C` is adjusted once for the protagonist and partner, and it writes out the four fields of the name area. Finally, the page status `801C6FB0` is set to 3 and fades out to the confirmation page. When the verification is rejected, the status is set to 1, the original name page is entered, and the log records `defaults-rejected`.

**Confirmation page**: "Start Story" writes the original exit flag `801C70F4 = 2` and calls the original to fade out; "Return" sets the status to 0 and returns to the casting page. The plot entrance still follows the original game logic. Changing the robot's name is outside the scope of this modification.

**Protagonist selection page** (2026-09-18): Original `801C50B8` In the browsing state, use the left and right keys (`801C34E4`) to cycle 0–3 in `801C70FA`, A When opening "はい／いいえ" and "はい", if the route is different from the last confirmed one (`801C70B0`), fill in the 30 characters in each of the two name areas as `0x1549` and call `801C3744` to load the default name of the route, and then set the status word `801C6FB0` 1. Write down the route and call fadeout `80099814(5,1,2)`; the original version does not have a return key. When the native page is determined, it is executed in the same order on the game thread (including the 0xB7 confirmation sound of `8007E8A8`), without going through "はい／いいえ", and then the default name (see above) is written; the 0xB9 cursor sound is played once per step during browsing. The default name on the card is read from the same set of tables used by `801C3744`: first name `801C6C00`, last name `801C6C70`, each route has 7 codes, the partner is +0x38, and the end is completed with 0xCA (i.e. `0x1549`); each code is a word in the word selection table, corresponding to the text 0 table id A glyph for `0x147F + 码`. When decoding fails (unrecognized glyphs appear), the original page is retained, and the default name is still written after the original "はい". `tests/test_protagonist_select.py` checks the eight key instructions of the default name and "はい" path against the ROM, `tests/native_name_entry.cpp` overwrites the selection, writes the default name and nickname truncation, reloads the template when the route changes, returns and starts the confirmation page, and starts directly with the original "はい".

The first actual test found that when the card is read from the keyboard or `performClick:` is triggered, an exception will be thrown. It has been changed to read only on mouse events.

Window scaling also fixes the size synchronization of the fixed Plume version: SDL may update `CAMetalLayer.drawableSize` first, and the original `MetalSwapChain::resize` skips the update of the drawable description when the sizes are the same, causing subsequent framebuffers and native dialogue to still be drawn at the old size. The controlled patch for `prepare_rt64.py` moves description updates outside of this condition, preserving dependent version locks and pre- and post-SHA-256 checks. The actual machine check adds an assertion that the size of `dialogue-raster.json` is consistent with the window after returning to the plot.

`Request.visible` is separated from `active`: Pages are preserved during casting to confirmation transition, return to casting, and exit wait. Each RT64 workload records whether the original screen should be covered, and the corresponding basemap is cleared at the end; scene failure is judged by overlapping code address intervals (the subsequent prologue is loaded from `801C4500`), and the overlay is removed only after the exit frame is completed. Test screenshots should use real game window screenshots. The GPU readback alone will only contain the named background and cannot be used as visual evidence of the page.

`src/srw64_native/name_assets.py` Extract eight original avatars from the character route table and face resource table of the original ROM. In HD mode, the HD version of each avatar is taken from the entire avatar set (see [Character Avatar HD](native-portraits-hd.md)), and the casting page is no longer registered separately.

The full name is connected with the original `0x00E7` midpoint, the string is terminated with `0xFFFF`, and only the original glyph is stored in the field. The `E000..E81E` virtual word record previously prepared for "Return and Change" is deleted along with the edit page.

While the page is open, all game buttons and joysticks are blocked, as well as Esc to exit the game and F6 to cut images. After leaving the page, wait for the relevant physical keys to be released before resuming game input to prevent Z/X penetration in Enter, direction keys, and input. This physical release check belongs to the macOS platform layer. It only waits once each time the page is closed, and is only counted when the game window has focus. 2026-09-18 Correction: The previous check continues every frame after closing, and any game keys held down thereafter (E+Z fast forward, I/K font size, Q review, E+Enter skip in the route prologue) will be blocked as "still being released"; it reads the system-level keyboard status, and typing in other applications will also block game input.

## Verification and Evidence

The current page is driven by [Debug Interface](../guide/debug-interface.md): `ui.click` and `ui.key` operate cards and buttons, `status.name_page` gives the current request (the casting page is attached with the Japanese default names of the four routes); the name writing and starting are recorded in `name-entry-events.jsonl` (`selected`, `back`, `started`, `original-started`, `defaults-rejected`).
- Offline probe `srw64-ui-probe` (`cmake --build build/recomp/gfx-build --target srw64-ui-probe`) can draw these two pages without opening the game: `--dialogue` gives it the avatar of `name_entry_assets` and the initial body posture of `battle_assets.units`, `--density` is the dp ratio of the host (simulated Deck extra-large transmission on Retina Mac 2.96, standard file 2.0), in the script `resize`/`capture`/`click`/`key`/`language`. The fixture uses the eight default names of the ROM and the initial body name of each route. Press `content/locales/terms/<语言>.json` and `default_names` and `units` to change to the reading language. For the avatar, press `route_faces` for the route. This is how the 2×2 version of 2026-09-30 is checked in three sizes: 1280×800 extra large, 1280×800 standard, and 960×720, and in three languages. RmlUi has no typesetting assertion.
- Two pitfalls of RmlUi: `display:flex` text written directly in the container is not displayed and must include `<span>`; when the flexible box is embedded in the flexible item `flex:1 1 0`, RmlUi will sort it again according to min-content, and the rounding error triggers the `containing_block.x >= 0` assertion - the four cards on the confirmation page are therefore changed to explicit widths.
- `tools/recomp/verify/verify_shared_ui.py`: Casting, confirmation page trilingual name, settings, zoom, return and start.
- `tools/recomp/debug/check_name_entry_ui_switch.py`: Original/modern page switching, original "はい" starts directly.
- `tools/recomp/debug/check_dialogue.py`: In a new game, use Enter to complete the selection and confirmation of the protagonist and enter the plot.
