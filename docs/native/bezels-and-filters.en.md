# Frames and filters (RetroArch compatible)

Date: 2026-10-05. Set three lines on the "General" page: **Frame**, **Filter**, and **Filter Row Number**. The filter supports Metal (macOS), Vulkan (Linux, Steam Deck, Android; MoltenVK can be used on Mac to try; passed on Steam Deck on 2026-10-06, passed on Android on 2026-10-07) and D3D12 (Windows, added on 2026-10-06, see §2). User-defined: the frame is only available when the aspect ratio is set to 4:3 (widescreen still fills up); the filter must be compatible with all slang presets of RetroArch, so run it with librashader instead of writing your own shader.

## 1. Usage and Table of Contents

Click "Select..." in the settings to open the list of step-by-step browsing. The starting points are listed in this order, appearing only if each exists:

| Start | Filter | Frame | Description |
| --- | --- | --- | --- |
| **Built-in** | `filters/` next to the program | `bezels/` next to the program (currently there is no built-in frame) | Distributed with the installation package, players do not need to touch it. macOS is in `.app/Contents/Resources/`, Linux is in the program folder; the development build is copied from `build/filters` to the host by CMake |
| **Mine (added by yourself)** | `filters/` of the data folder | `bezels/` of the data folder | It is automatically created when you open the settings for the first time, and a trilingual `README.txt` is placed in it to explain what to put; there is "Open this folder in the file manager" in the list on the desktop |
| **RetroArch comes with** | `shaders/shaders_slang` | `overlays/` | Only available with RetroArch installed: macOS `~/Library/Application Support/RetroArch`, Linux `~/.config/retroarch`, Flatpak `~/.var/app/org.libretro.RetroArch/config/retroarch`, Steam version, Windows `%APPDATA%\RetroArch` and `C:\RetroArch-Win64` |

The data folder is the one next to the archive (macOS `~/Library/Application Support/srw64-recomp`, Linux/Steam Deck `~/.local/share/srw64-recomp`, Android is application-private `files/user`). Steam Deck does not display "Open in file manager"; on Android, it opens the system "Files" App: the application brings a DocumentsProvider (`UserFilesProvider.java`) and puts the entire data folder (archives, filters, frames, HD packages) as the "Marchwind64" location into the "Files" App and the file selector of all applications, where the player puts RetroArch Copy the filter folder and frame image in (copy the folder and the subdirectory together), and the button in the settings can be directly opened to the corresponding subfolder via JNI (`SRW64Activity.openUserFolder`). Neither shows the window size or display mode.

- **Players add their own filters**: Copy the RetroArch preset (`.slangp`) together with the `.slang` and images it uses into "My" `filters/`, keeping the original folder structure (many presets refer to `../include` or `../../include`), and the subfolders are arbitrary. The browse list will re-read the folder every time it is opened, and there is no need to restart after adding it.
- **Players add frames themselves**: `.png` with a transparent window in the middle, or RetroArch overlay `.cfg` (`overlay0_overlay = 图片名.png`) pointing to it, put "my" `bezels/`. The transparent window automatically aligns with the 4:3 picture (§3).
- **Built-in filters**: `tools/content/fetch_filters.py` Take 9 presets and all the files they use (according to `.slangp`'s pass, texture, `#reference` and `.slang`) from the fixed commit of libretro/slang-shaders (`1e0238f`, 2026-10-05) `#include` (chased one by one), keep the path in the warehouse, a total of 35 files, about 316 KB, placed in `build/filters`, with `NOTICE.txt` attached (source and "state the author's permission at the beginning of each file"). List: crt-lottes (curved surfaces, shadow masks), crt-easymode (flat, clean scan lines), crt-geom (curved surfaces and rounded corners), zfast-crt (very light, suitable for handheld machines), crt-guest-advanced- fast (more options, heavier), scanline (only scan lines), ntsc-adaptive (composite video bleeding), sharp-bilinear (sharp pixels of any size), xbrz-freescale (smooth pixel painting). `build_release.py`, `build_linux.py` (Linux build containers cannot be connected to the Internet, so `build/filters` must be taken from a networked machine first) and put it into the `filters/` of the package.
- **No built-in frame**: Ready-made N64 frames (libretro/overlay-borders, MIT) are all printed with Nintendo's trademark (N logo, NINTENDO64) and are only used in official website demonstrations and are not distributed with packages; players can put "my" `bezels/` themselves.
- **Number of filter lines**: The height of the screen read by default. The default "240 lines" = the number of lines in the original version, which is most similar to the CRT type; 480/960 lines are clearer and the scan lines are thinner; the "window" is the pixels of the window itself.
- Three items are saved with `presentation.json` (`bezel`, `filter` are absolute paths, `filter_scale` is 0–4).

## 2. How to connect the filter

- **librashader** (v0.12.0, MPL 2.0): Loaded at runtime (`dlopen`; Windows uses `LoadLibraryW` to find `librashader.dll` next to exe). Without it, the host runs as usual, and the settings say "This version cannot yet use filters." `tools/recomp/toolchain/fetch_librashader.py` into `build/recomp/thirdparty/librashader/<系统>/`:
- macOS: Get the official release package (check SHA-256, only bring Metal and OpenGL). CMake copies `librashader.dylib` to the host; the release version puts `build_release.py` into `.app`'s `Contents/MacOS`, and the license into `Resources/licenses`.
- Linux/Steam Deck: Official binaries are not released. Compile with Cargo according to the fixed commit (`87e8a97`) in the Linux build container (Rust 1.97.1, `tools/release/linux/Dockerfile` is installed in the container), and only open the Vulkan runtime; `build_linux.py` Put `librashader.so` into the package's `lib/`, and the license is entered `licenses/`.
- Android: `fetch_librashader.py --android` Cross-compile arm64 with clang with fixed NDK, only open Vulkan (`rustup target add aarch64-linux-android`). Libc++ is statically linked in (rustc links the default library without a driver, so `-lc++_static -lc++abi` is written at the end of the link; setting only `CXXSTDLIB` or `-static-libstdc++` will leave undefined libc++ symbols, and `dlopen` refuses to be loaded). The library only depends on libc/libm/libdl. `build_game.py` Adjust it yourself and `fetch_filters.py`: `librashader.so` is put into the APK's `lib/arm64-v8a` (the host is based on the library name `dlopen`), and the built-in filters (except crt-lottes, see the Android actual test in §4, user determined on 2026-10-07) `assets/resources/filters`, solved by SetupActivity to `files/resources/filters` (`bundled_resource`). CI's android task caches compiled libraries by script hash.
- Windows: Also compiled with Cargo according to fixed submission, only D3D12 and Vulkan runtime are enabled (compiled in the Windows task of CI, the compiled library is cached according to the hash of `fetch_librashader.py`); the exe in the package contains `librashader.dll` and `filters/`, and the license is `licenses/`. **No official Windows distribution package**: It comes with D3D9 runtime, imports `D3DX9_43.dll` (only available in old DirectX redistribution packages), and fails to load on clean Windows (error 126). The settings always show "cannot use filters" - this is one of the reasons why filters cannot be used in the Windows version (the other half is that the host does not have Windows loading and D3D12 code at all). D3D12 runs lazy-loaded `dxcompiler.dll`, using the one included with RT64 in the package.
- `--from-source` Compile from source on any machine; compile a version with Vulkan on Mac, try Vulkan way (`check_filter.py --vulkan <库>`) with `SRW64_GRAPHICS_API=vulkan` (MoltenVK) and `SRW64_LIBRASHADER=<库>`.
- The "About" page notes the librashader and license.
- **Position** (`capture_frame` of `graphics.cpp`): RT64 Draw the game screen (including our HD layer) into the swap chain. After we finish drawing the dialogue, the interface is drawn in two passes:
1. The pages that belong to the game screen (Library/Battle Appreciation/MOD words on the title page, inter-game and pre-battle pages, name pages, etc.) are drawn first;
2. The filter acts on the rectangle of the screen (game screen + dialogue + these pages);
3. Draw the rest of the interface on top and keep it clear: settings window (including picture book, battle appreciation, MOD management), prompts, frame rate, frame, touch screen buttons, version number and setting button on the title page.
- **How ​​to divide it into two passes**: Put an `<layer-mark>` (`chrome='1'` means category 3) at the beginning of each interface document. When it is drawn, it tells the rendering agent which layer the next geometry belongs to; the agent (`LayeredRender` of `frontend.cpp`) discards the drawing of another layer in each pass. The second pass of the same frame cannot wait until "the previous frame interface is still on the GPU" (it will lock itself), nor can it reset the vertex buffer of the renderer (the command of the first pass has not been executed yet): `prepare_frontend.py` adds `start(…, continue_frame)` to the renderer adaptation layer. When there is no filter, the painting is done in one pass.
- **The words on the title page follow the screen**: The position of Library/Battle Appreciation/MOD is calculated according to the rectangle of the screen (leave 6% in each of the lower right corners). At 4:3, it is inside the screen, will not be covered by the frame, and can also be illuminated by the filter.
- **Every frame**: Copy the picture rectangle from the swap chain into a texture → use our own pass-through default (a linear plus mipmap pass, written in `filter-passthrough/` in the run directory) to the height specified by "number of lines" → the player's default returns the same rectangle from this small picture. Skip shrinking when "Window" is selected for the number of rows. There is a lower limit on the number of lines: at least 480 lines (`kHdScale`) when opening HD images, to prevent the HD material from shrinking to the original resolution), and at least 720 lines (`kPageScale`) when there is our interface page in the screen (the first time we draw something) - 12–16 dp words only have 3–5 lines under 240 lines The line height is too high and the Chinese characters cannot be recognized (2026-10-06 user requested "I want a filter effect but also see it clearly"). Press the player's when the number of rows selected by the player is higher.
- **Compile** is placed in the background thread, and the next frame is replaced after compilation; the replaced old chain will be released after 4 frames, so as to avoid the GPU still being used. Metal directly uses the RT64 command queue (Metal queue can be submitted by multi-threads); Vulkan uses delayed creation (`libra_vk_filter_chain_create_deferred`), upload commands are entered into our own command buffer, and plume's queue lock (`VulkanQueue::mutex`) is taken when submitting, and does not compete with RT64 submissions.
- **D3D12**: Use non-delayed `libra_d3d12_filter_chain_create` (it builds its own queue on the background thread to upload and waits until it is completed. The D3D12 queue can be used by multiple threads); the copy and state switching of each frame share plume's `barriers`/`copyTextureRegion` with Vulkan, and the image is `ID3D12Resource*` (`LIBRA_D3D12_IMAGE_TYPE_RESOURCE`) is passed, and the view is built by the filter chain itself. librashader will replace `SetDescriptorHeaps` with its own descriptor heap, adjust `notifyDescriptorHeapWasChangedExternally()` after drawing and clear the pipeline, layout, topology and framebuffer remembered by plume, allowing the interface to be re-bound. The target stops at `RENDER_TARGET` after drawing, which is consistent with the `COLOR_WRITE` recorded by plume.
- **Vulkan details**: The swap chain image is not formatted in plume. According to the RT64 convention, when B8G8R8A8 (Android R8G8B8A8) tells librashader, otherwise it will build render pass times `FORMAT_NOT_SUPPORTED`; copy and layout switching use plume's `barriers`/`copyTextureRegion`, librashader After painting, let plume rebind its pipeline and framebuffer.

## 3. How to draw the frame

- The picture position does not move: Find the transparent window in the picture (find the range with alpha < 128 from the center of the picture to the surroundings, `bezel.hpp` of `find_hole`), stretch the entire picture until the window just covers the 4:3 picture, and crop the part beyond the screen (`place`). In this way, the coordinates of all things drawn close to the screen (dialogue, native pages, HD layers) do not need to be changed. Frames with windows other than 4:3 (such as RetroArch's `tv-integer`, which has a window of about 1.14:1) will be slightly stretched horizontally.
- The opaque image in the center is treated as if there is no window, and the entire image fills the screen.
- **Page indentation 4:3 area** (2026-10-06 user selected): When the screen ratio is set to 4:3, our interface pages (protagonist selection, inter-game, pre-battle, Link Battler, title menu, etc., excluding chrome such as settings windows) are only typeset in the 4:3 screen (`frontend.cpp` of `page_area()`), and the frame no longer presses both sides of the page; dp Also based on this area, when the Deck is extra large, the page still has 800 × 600 dp. The method is to add a transparent border to the page body (RmlUi only draws the background in the padding box, so the page background color will not cover the frame), and the positions of elements absolutely positioned by window pixels (those aligned to the original 320 × 240) remain unchanged, because the unpositioned body is not their containing block. The protagonist selection page is typeset by itself, and the same area is obtained through `NamePage::set_area`. Offline audit added `deck-4:3` size (`run_audit.py --sizes deck-4:3`), 204 pages with zero issues.
- Drawing method: An RmlUi document (`bezel_sync` of `frontend.cpp`) placed at the bottom of all interface documents, `PushToBack` for each frame; above the dialogue and below other interfaces.
