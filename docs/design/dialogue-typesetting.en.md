# Dialogue typesetting: display more words and turn less pages

Date: 2026-09-23. The goal set by the user is to display as many words as possible in the dialog box and reduce the number of times pressing A to turn pages. This article records the font and typesetting rules set for this, the data based on it, and the original places that need to be changed.

For the current typesetting implementation, see [Chinese-Japanese-English cross-platform text and game dialogue](../native/portable-text.md), for the line file format, see [Line Text File](../guide/dialogue-text.md), and for translation sources, see [Full Text Localization Planning](translation-plan.md).

The decided plan: HarmonyOS font; keep the name in the box but tighten the name line, and the text area is about 43 inches high; Chinese size 13 and English size 11 are both 3 lines per page; one line of dialogue is arranged in a row; use dynamic planning to select the page turning position.

- 24% fewer page turns for Chinese and 37% fewer for English, both languages have fewer pages than the Japanese original.
- Page-turning cuts in the middle of sentences: down from 3,856 to 199 in Chinese and from 4,692 to 409 in English. The number of pages remains unchanged, only the page turning position is changed.

Source of numbers:

- Character width does not include kerning, and the English language will actually be slightly narrower.
- The protagonist's name is calculated as three characters (five letters in English).

### 2. English symbols are 0.85 times the set value

I/K still only adjusts one font size, and the number displayed in the bottom column remains unchanged; the English text is arranged at 0.85 times this number (when setting size 13, the English size is 11). When F7 switches languages, the number of pages on both sides and the reading rhythm are similar. The typesetting engine originally accepts decimal numbers; the font sizes in `typeset()` and Reader are now integers and need to be changed to decimals.

### 3. One line of dialogue is arranged in a row, and the original page turning point is only used for synchronization.

- **Display:** All the fragments of a record (the original paragraph that is turned out each time by pressing A) are connected into a paragraph of text, and the pages are re-paged according to the current font size and frame size. Chinese are connected directly; English are connected with spaces.
- **Synchronization:** The original script still needs to confirm each page turning point one by one (`<STOP>`). When the page turned by the original version already contains the beginning of the next paragraph, the previous page turning point will be confirmed for the original version in the background; if the original version does not respond within 0.5 seconds, it will be sent again. The original text is originally covered by the original, and players cannot see this process. After pressing A on the last page, first confirm the remaining page turning points, and then confirm `<END>` to enter the next dialogue. The original version confirms that it will only move forward, not backward. In the event record, each background confirmation is recorded as `guest_stop`, and the confirmation END is recorded as `guest_confirm`.
- **The number of fragments is based on the Japanese ROM (guaranteed):** If the `---` of the translated text is less than the original text, the missing confirmation will be placed on the last page and filled together; if it is more than the original text, the extra fragments will only be treated as ordinary sentence fragments, and will not get stuck or misjudged. The line file check still requires the number to be consistent.
- **Line files remain unchanged:** The number of `---` must still be consistent with the original text. It is the basis for aligning the original and the original text and no longer determines how to paging on the screen. There are currently more than 45,000 translations that do not need to be modified. After native implementation, the description of `---` in [Line Text File](../guide/dialogue-text.md) was changed to "Original page turning point; re-page in the game according to the size of the frame."
- **Preserve Pause:** The verbatim display will stop for 18 frames (0.3 seconds) when it reaches the original page turning point, and the original pause created by page turning will be retained.
- **Do not merge across records:** Between the two lines of dialogue are script commands. The script may change avatars, move units, or play sound effects.
- **No forced page turning mark for now:** The goal is to reduce page turning. Where line breaks are really needed, use the line breaks in the lines file.
- **Not included in the scope:** Combat lines (only replaced and displayed, advancement is timed by the original version) are not included in this column, and are still processed according to the current reduced font size.

### 4. Keep the name in the box, tighten the name line, and change the text area from 35 high to about 43 high

The name line now takes up about one-third of the height of the box. The native session produced three types of brand renderings: labels embedded in the border, border gaps, and capsules outside the frame. After reading it, the user decided to keep the name in the box and chose the "Tighten Name Line" version:
- Use size 10 font for your name and place it in the upper left corner of the box;
- The main text is immediately below the name, and the main text area is approximately 43 inches high.

This only changes the display and does not touch game data.

The height of the text area is compared with 42, 43, and 44:
- **42:** Chinese No. 13 can only put 2 lines, no.
- **44:** The default font size is exactly the same as 43, only there is one more line for certain font sizes: Chinese setting is 10 points, and English setting is 11 points. When the English setting is 15, 44 is stuck exactly on the boundary of 3 lines, and the result is unstable and does not count as a profit.
- **Conclusion:** Take 43; if there is just one more pixel in the layout, 44 will also work.

### 5. The number of lines per page is adaptive according to the font size

- **Current problem:** The line spacing is fixed at 1.22 times the font size. When the text area is 35 high, only one line of sizes 15–18 can be placed.
- **New rules:** First calculate how many lines can be placed according to the minimum line spacing (1.08 times for Chinese, 1.15 times for English), and then divide the remaining height evenly among the lines, with a maximum line spacing of 1.22 times.
- **Text area is about 43 seconds long** (each line of dialogue is arranged in a row, the number of pages is the number of page turns of all plot dialogues; the English text size is 0.85 times the set value):

### 6. Use dynamic programming for page turning position

- **Candidate position:** The legal line break position given by ICU.
- **Comparison order:**
1. Minimize the number of pages, and the result is the same as "filling as many pages as possible in one line";
2. Cut in the middle of the sentence the least number of times (period, question mark, exclamation mark, ellipsis, and closing quotation mark all count as the end of the sentence; the original page turning point only counts as the end of the sentence in Japanese);
3. Cut at commas and pauses as few times as possible;
4. There are at least one or two words or one English word left in the last line (punctuation and quotation marks do not count as words, "Up!" counts as one word);
5. When all the above are the same, the previous pages are full (the latest starting point is taken).
- **2026-09-24 Three adjustments** based on the lines with added punctuation at the end of the page (native `a6a70ed`):
- In the original version, the page turning point used to count as the end of the sentence in all languages, but now it only counts in Japanese. After the punctuation is completed at the end of the Chinese page, the original page turning places that have not yet been punctuated are filled with a sentence that continues across the page (such as "Come | to walk with you" and "Master will be | weeping"). The original rules will specifically select these places to turn the page. The 0.3 second pause remains unchanged.
- At the same time, the previous pages are full: for example, the first page of 17358 originally only had "You are the fool.", but now it is "You are the fool. It is helpless for the guerrillas to lose in battle.".
- When counting the number of words in the last line, punctuation and quotation marks will not be counted: otherwise "Up!" will count as 3 words, and 17364 will leave it alone on the last page after the previous page is filled.
- Extract 1,500 multi-page records, the number of pages remains completely unchanged:
- Chinese: page 116 → 31 cut in the middle of the sentence, first page with only one line 156 → 55;
- English: pages cut in the middle of sentences 229 → 80, first page with only one line 164 → 77;
- Price: 118 → 147 with only one word left in the last line of English.
- **Computational amount:** There are only dozens of candidate positions for each record, which can be ignored.
- **Don't do it:** Continue to use the current method within the line (one line should be filled as much as possible, which is the minimum number of lines); no justification and hyphens.
- **Character classification (common to C++ and Python):**
- End of sentence: `。！？…!?.` and closing quotation mark, right bracket `」』）”"`, plus original page turning point;
- Comma level: `，、；：—,;:`;
- End of line can be pressed to half width (clause 7): `。，、；：」』）》】〕`;
- Open quotation marks (skip together with the previous two groups when counting the number of words in the last line): `“「『（《【〔"`;
- Avoid sending head and tail to ICU according to strict rules.
- **Control test:** C++ and Python share a use case file. Write down each use case:
- Input: text, language, font, font size, width, height, forced page turning position;
- The intermediate quantity measured by C++: the end position and width of each grapheme, and the legal line break position given by ICU;
- Expectations: line spacing, lines per page, line boundaries, page boundaries, half-width punctuation positions.
  
Python uses these intermediate quantities to run the same set of rules, and the page boundaries must be exactly the same; the difference in word width caused by the font is not included in the algorithm comparison.

### 7. Press the punctuation mark at the end of the Chinese line to half width

- **Current situation:** "Character +." When it cannot fit, the head-and-tail avoidance rule will push this character together to the next line.
- **New rule:** Make the ".,,;:"　)》]" at the end of a line only half a word wide (consistent with the character list in Item 6).
- **Benefits:** One less word can be squeezed into the current font of approximately 5,360 lines.
- **Implementation:** SC does not have a halt function, so the width of the punctuation mark at the end of the line is halved when breaking a line. This is only done when an extra word can be added.

### 8. Change font size and switch language

- **Change font size:** Re-paginate the entire article, and set the beginning of the current page as the position where the page must be turned. In this way, the current page still starts from the same word, and only the following pages are rearranged. The original confirmation will only move forward and will not be affected.
- **Review:** Changed to save the entire record.
- **Switch language:** Replace the entire paragraph and continue reading from the beginning of the current fragment in the original version.

### Don’t do it yet: make the frame bigger

- **Added to ~51 tall (+8 pixels):** English 13 size setting has 4 lines per page, page turns dropped from 38,958 to ~35,900 (−8%), Chinese unchanged.
- **Added to about 57 high:** Chinese size 13 can also hold 4 lines.
- **Cost:** The frame needs to be enlarged to cover more of the map. Unit movement and cursor markings in the plot are in the middle of the screen.
- **When to look at it again:** Wait until the name line plan is seen on a real machine before evaluating it; when doing widescreen in the future, you can also extend the frame to both sides.
