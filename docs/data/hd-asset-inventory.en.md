# HD asset inventory: classification, map dynamic effects and Alibaba Cloud model selection

Date: 2026-09-23, 2026-09-24 to supplement the current status of various types. The inventory itself comes from static analysis. The game was not running at that time, and the charging interface was not called. For information on which access path to use for each type and which step to take, see [HD Planning](../design/hd-pipeline-plan.md); for actual measurements of previous models, see [Alibaba Cloud Benchmark](../design/hd-ai-benchmark.md).

The inventory tool is [`asset_inventory.py`](../../tools/content/asset_inventory.py). It decompresses all the resources of the ROM, determines the type and size according to the header, and then sorts them according to the resource number range, and writes the result to `build/content/asset-inventory.json`. The corresponding test is [`test_asset_inventory.py`](../../tests/test_asset_inventory.py). When ROM is available, the total number and the number of images in each major category will be checked.

**2026-09-23 Scope Decision**: Combat animation-related categories (battle sprites, weapon sprites, shields, cut-in, special effects, 3D battle backgrounds, battle HUD) are temporarily suspended; LoRA will not be trained, and style consistency will depend on reference pictures and batch-by-batch review.

There are two sources of intervals. The intervals with binding tables or existing extractors are marked as `table`; the rest are manually identified after rendering into pictures, and are marked as `inspected`. This article uses "visual inspection". Visual inspection can only explain the content of the picture, but not which screen it is on or which function it is drawn by.

### Airframe identification (map unit icon)

Each aircraft on the tactical map is a 16×16 SD avatar. Two elf sub-slots are built for each unit by `801C60A4`, both in mode 5:

- **Subslot 0**: The icon itself, priority 0x91, palette parameter is `1010 + 阵营`.
- **Subslot 1**: Shadow ellipse (resource 687), priority 0x92, drawn behind the icon.

The camp colors come entirely from the palette: 1010 blue, 1011 red, 1012 yellow, 1013 gray. Changing the palette of the same icon is another camp. The meaning of the corresponding camp of 1013, and whether "acted" will also be replaced by it, have not yet been confirmed. 1015 is not a color match for this group, and its use is yet to be investigated.

Numbers 1–6 of the palette are camp colors, numbers 7–13 are fixed colors (green eyes, pink, etc.), and number 0 is transparent. Therefore, the HD version must continue to change colors according to the palette, and cannot just make a set of RGB.

**Without AI**:
- In the actual measurement on 9-08, the 16-pixel body will be reconstructed into a new shape;
- 16×16 is also below the minimum input size for all services.

Use a deterministic pixel art upscaling algorithm instead. They are calculated directly from the local ROM and can be generated on first import without the need to distribute art files.

| Method | Effect | Color Palette | Conclusion |
| --- | --- | --- | --- |
| Bilinear (current situation) | Obviously blurry at 4 times the internal resolution | — | Need to change |
| nearest neighbor |
| Scale4x (EPX twice) | Slashes become smoother, still pixel style | **Only use primary colors**: Operate directly on the color map, one result applies to all camps | The first choice when retaining the pixel feel |
| hqx ×4 | Between the two, retaining more details and still having jagged edges | New colors will be blended | Alternative |
|
| Manual redrawing 64×64 | Best quality | Just draw according to the color map | 317 pictures are a lot of work, only for future options |

- **Color Mixing Algorithm** needs to be generated separately according to color palette: 317 pictures × 4 camps, about 1,300 64×64 pictures.
- **Access**: Use RT64 texture hash replacement. The icon is a 16×16 texture uploaded separately, and the hash itself distinguishes the color palette, which corresponds to "one copy for each camp".
- **Resolution**: One-to-one sampling at internal magnification 4; 8× version or mipmap available at higher magnifications.
- **MMPX (Tried)**: A sprite upscaling algorithm using only primary colors (McGuire & Gagiu 2021, MIT License). [`pixel_scale.py`](../../tools/hd_ai/pixel_scale.py) was transplanted to the color map according to the reference implementation (there is also Scale2x), and 5 icons were tried. The result was very conservative, almost maintaining the nearest neighbor pixel shape, and only trimming a few isolated jaggies. For this type of 16-pixel avatar with a lot of jitter, the improvement is not as obvious as Scale4x.
- **AI option**: 16×16 only has 256 pixels of information. What AI does is actually "redraw", not "enlarge". To fill in the real details, you have to give it additional sources of information. According to this idea, candidates are divided into three categories, and they must be tested with 5 pictures first:
1. **Pixel painting dedicated generation service**: The output is still pixel painting, but the size is larger and the details are more, suitable for "preserving the pixel style".
- Resize of [PixelLab](https://www.pixellab.ai/docs/tools/resize) uses AI to redraw pixels to new sizes, ranging from 16–200 px. It is recommended to enlarge up to 2 times per step (16→32→64). The documentation says it is only available in the Aseprite plug-in; there is also [API](https://api.pixellab.ai/v2/docs), but it remains to be confirmed whether it has equivalent functionality.
- [Retro Diffusion](https://retrodiffusion.ai/) provides pixel art model, supports img2img (adjustable intensity), transparent background, and limited output palette.
- Both are overseas commercial services, which require registration, and the price must be confirmed after registration. You can limit the output to the original 14 colors of the icon, and then map it back to the color map, and all four camp colors will automatically take effect.
2. **Universal image editing model + reference image**: suitable for "HD smoothing". Send the 16×16 icon together with the battle sprite of the same machine body (a pixel art of 97 px or more with the same shape in the ROM), and let the model redraw the icon according to the shape of the sprite. This article only uses the battle sprites as a reference, and does not involve the postponed battle animation HD.
- The failure of 9-08 was precisely because there was no reference picture.
- Available `qwen-image-3.0` (3 input images) or `wan2.7-image` (9 reference images). Each candidate of 317 tickets costs about 63 yuan.
- After the output is reduced to 64×64, the color numbers are also quantized back to the original palette.
3. **Community pixel super-resolution model**: Runs locally, free of charge, but they are all old models trained with cartoon images in 2020.
- [4x PixelPerfectV4](https://openmodeldb.info/models/4x-PixelPerfectV4): WTFPL licensed, feel free to use.
- [4x Fatal Pixels](https://openmodeldb.info/models/4x-Fatal-Pixels): CC-BY-NC-SA licensed, not for commercial use.
- `4x xbrz`, `4x scalenx`: Just use the network to imitate the algorithm of the same name.

They have no additional source of information, are close to a learned xBR, and have the lowest priority.
- **Vectorization**: Kopf–Lischinski's [Depixelizing Pixel Art](https://www.cs.jhu.edu/~misha/ReadingSeminar/Papers/Kopf11.pdf) is not AI. It converts pixel art into smooth vector outlines that can be arbitrarily enlarged and retain the original color areas. Inkscape's "Tracing Bitmap → Pixel Art" uses it ([libdepixelize](https://gitlab.com/inkscape/devel/libdepixelize)). It ignores the transparency channel and handles outlines separately. This machine has not been installed and is not included in the comparison.

## 3. Dynamic effects of tactical maps

This section comes from a static reading of `801C6EFC`, `800945D4`, `8009CB04`/`8009CC0C`, `800858DC`, and the 3D34 implementation `8020A874`. "Jump" is the execution of the tactical main loop `801DFBD0` once; 1 jump and about 2 VIs are speculations without verification.

### 3.1 Map Record

12 bytes per record:

```text
u16 layout, atlas, palette, aux1, aux2; u8 模式; u8 参数
```

`group_count` is the number of tiles after deduplication. Each group corresponds to a tile and its placement list, and has nothing to do with animation. There is no code to rewrite a single cell during operation: the readers of the layout can only draw, take terrain and take dimensions, all of which are read-only. Placement flag `0x2000` appears in map 43, 45, 47, 119, 444 in total, and no code reads it.

### 3.2 Water surface: Palette cycle (code confirmation)

- **LOAD**: non-zero aux1/aux2 loaded by `8009CB04(通道, 资源)`, channel recorded at `80178D50 + 通道×0x12`.
- **PUSH**: `801DFBD0` calls `8009CC0C` per hop. When the countdown reaches 0, the color of the next frame is written directly into the map palette resource (slot 0x3B). `800945D4` TLUT is reloaded every frame, so writes appear immediately. The gating conditions are `8010279D != 0` and `80178C6A & 0x81 == 0`, whether the menu or pause is frozen has not been checked.
- **aux resource format**: `u8 帧数 F, u8 起始色号 S, u8 颜色数 N` first, then F bytes of hops per frame, then N×F RGBA5551. The offset of frame c of color f is `3 + F + (c×F + f)×2`. All 16 resources are of similar length.
- **Water surface parameters**: 6419–6424, color number 0xC0–0xD0, 17 colors × 9 frames × 9 jumps per frame, 81 jumps in one round.
- 38 map references, 36 of which do have pixels of these color numbers in their atlases.
- The water area is large: Map 56 has 1,489 / 2,700 cells, about 205,000 pixels; Map 13 has 834 cells.
- **Other loops**:
- 6426: 0xB0–0xBE, 5 maps
- 6427: 32 frames, map 7
- 6429/6430: 0x15–0x17 red pulse, map 0, 19, 20
- 6431: Flash with one frame per jump, 17 maps
- Also 6428, 6432–6435 for lighting, lava and cosmic effects
- **Total**: 67 maps have visible palette animations. Another 28 pictures reference aux, but there are no pixels with corresponding color numbers in the atlas, which are invalid references (4, 23, 65, 104, 111, 113–118, 137, 140–155). For a list of each map, see [Tactical Map List](tactical-maps.md).
- **Example**: Map 20 of the heroine's first episode, 6422 is a river (66 squares), and 6429 is a 6-square red pulse.

### 3.4 Impact on HD

Conclusion: Texture hash replacement won't work here. The TLUT or atlas content of the cycle color and colony grid changes with each hop, and so does the hash. The tactical map needs to be taken over in its entirety. For implementation and verification of the map 20 template, see [HD Planning §3](../design/hd-pipeline-plan.md#3-战术地图).

The core idea is "high-definition base map + high-definition color number map + real-time color palette of the game frame". The advantage is that there is no need to re-implement the circular logic: whatever the game writes in the palette, the high-definition screen will display accordingly. According to this idea, various types of dynamics are handled as follows:

| Dynamic | Processing | Required HD assets |
| --- | --- | --- |
| Water surface, light, lava, red pulsation, flash (palette cycle) | The shader checks the frame palette according to the color number, and the timing and pause gate control are consistent with the original version | One color number map for each map, no frame-by-frame assets required |
| Night scene, daytime, darkening, full black (3D34 same layout but change color palette) | The same mechanism automatically takes effect | None |
| Comic-style map replacement, local variation (3D34 layout change) | Treat as another map | Based on the previous step, only redraw the changed 18–29 cells |
| Colony rotation | Superimpose an 8-frame sprite, the frame number reads `80178C6D` | 8 frames; generated together in one request to ensure consistency between frames |
| Vibration, scrolling | Read lens offset for each frame, automatically follow | None |
| Fade in and out | The overlay is drawn on the map and is not affected | None |
| Overview zoom | The same set of textures are reduced and drawn, relying on mipmap to ensure image quality (implemented) | None |
| Terrain panel | The first version retains the original drawing, and will sample the sub-rectangle of the high-definition image in the future | None |

Other points:

- **Filter by resource**: `800945D4` is also used to draw concentration lines 610–612. When taking over, it must be identified according to the map layout resource number to avoid mistaken takeover.
- **Asset Key**: HD assets are keyed according to the layout number. The color palette is not entered and the color is determined at runtime.
- **The animation area is not handed over to AI for redrawing**: The color number map of the water surface and other areas is enlarged using an algorithm that only copies the original color number (MMPX is used for the sample, the same set of tools as the body identification). The method is the same as the coastal protection of the world map. In this way, the shape of the water pattern is smoother and the movement is the same as the original version. The AI ​​is only responsible for details in static areas.
- **Optional Enhanced Water**: A slow-moving detail texture is overlaid in the shader, with colors still taken from the current frame palette. This is a new performance and must be turned on and off separately.

### 3.5 World Map

There is no animated sea surface under the world map. The transparent sea area displays the clear screen color RGB(0,55,90), which is set by `801C3490`. If you want to draw the sea surface in the HD version, it is a new content and needs to be turned on and off separately, which cannot be counted as restoration. Only area 5599 will draw starry sky 5582 in slot 0.

Restrictions affecting this project:

- **Transparency Channel**: Generative models neither receive nor output transparency. Alpha continues to be taken from the original image mask ([`portrait_matte.py`](../../tools/hd_ai/portrait_matte.py) for the avatar). Only ordinary super scores can directly retain RGBA.
- **Minimum Size**: 16×16 grids and icons that are lower than the minimum input of all services will be sent as an atlas or the entire image, and are pre-enlarged by nearest neighbor first.
- **Scale**: Chapter titles are about 7.9:1, only accepted by wan2.7 and qwen 3.0; production exceeds the limit of 2:1.
- **Offline**: The international station announced that the old series `qwen-image-edit` and `qwen-image` will be offline on 2026-10-10. The replacement is 3.0, which does not affect the four models tested in the benchmark. The text of the domestic announcement was not captured.
- **Interface details**: The wan2.7 documentation lists `prompt_extend` and `negative_prompt` as not supported, while [`aliyun.py`](../../tools/hd_ai/aliyun.py) passes `prompt_extend:false` for all models. It needs to be changed before the next batch of wan2.7 requests.
- **9-08 Super score failure**: 403 It may be related to the upload path prefix of the temporary bucket, but there is no confirmation. In the future, you will switch to the local upload of the SDK or build your own OSS in the Shanghai region.
- **Auto QA**: Mainly based on deterministic indicators (mask IoU, color difference after shrinking to original size). The visual model only makes the second judgment and does not serve as the sole acceptance.

It can also be mixed: all the avatars are painted with super score first, and only the main characters are redrawn in a natural way.

- `wanx2.1-imageedit` 0.14 yuan, is an old version, the super score function is no better than VIAPI super score.
- The free quota for new users is not written on these pages. You need to confirm it on the console.

**Puzzle batch processing**: `qwen-image-3.0` Priced per piece, 1K and 2K outputs have the same price, and the maximum output area is 2048². Therefore, you can put several avatars into one grid and input them, request a 2048² picture at a time, and then cut it.

| Spelling | Output per grid | Unit price of each avatar | 304 photos in total |
| --- | --- | ---: | ---: |
| Single sheet (current practice) | Maximum 2048² | 0.20 | 61 (1 candidate) |
| 2×2 | approx. 1024² | 0.05 | approx. 15 |
| 3×3 | about 680² | 0.022 | about 7 |
| 4×4 | Approx. 512² | 0.013 | Approx. 4 |

The target is 384² (4x), so 3×3 will also suffice. The risk is that the model may mix the features of adjacent cells together, or treat each cell inconsistently. Mitigation methods:
- Leave neutral color space between grids;
- Characters from the same work are placed on the same sheet;
- The prompt words indicate that each grid is independent.

Character styles in the same picture will naturally be consistent, which is actually a benefit. 2×2 has been tried and true: `portrait_batch.py` got all 300 in 75 requests.

The amount itself is not the bottleneck, the main cost is in review and consistency control. Before batch requests, freeze the input and prompt words according to the rules of [Benchmark](../design/hd-ai-benchmark.md), and do not submit duplicate requests if there are already request records.
